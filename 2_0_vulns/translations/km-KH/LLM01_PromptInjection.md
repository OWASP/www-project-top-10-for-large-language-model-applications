# LLM01:2025 Prompt Injection

## ការពិពណ៌នា

ភាពងាយរងគ្រោះដោយសារ​ Prompt Injection កើតឡើងនៅពេលដែល prompt របស់អ្នកប្រើប្រាស់ បែរជាផ្លាស់ប្តូររបៀបបញ្ចូលសំណើ ឬលទ្ធផលរបស់ម៉ូឌែលភាសាធំ (LLM) ដោយមិនបានរំពឹងទុក។ ការបញ្ចូលទាំងនេះអាចមានឥទ្ធិពលដល់ម៉ូឌែល ទោះបីជាវាមិនអាចមើលឃើញ ឬអានបានដោយមនុស្សក៏ដោយ។ ដូច្នេះ Prompt Injection មិនចាំបាច់ត្រូវមានក្នុងទ្រង់ទ្រាយដែលអាចមើលឃើញ ឬអានបានដោយមនុស្សទេ ខណៈដែលវាត្រូវបានយល់និងបកស្រាយដោយម៉ូឌែល។

ភាពងាយរងគ្រោះដោយសារ Prompt Injection មានមូលហេតុមកពីរបៀបដែលម៉ូឌែលដំណើរការព័ត៌មាន prompt និងរបៀបបញ្ចូលទិន្នន័យអាចបង្ខំឲ្យម៉ូឌែលបញ្ជូនទិន្នន័យ prompt ខុសទៅកាន់ផ្នែកផ្សេងទៀតនៃម៉ូឌែល ដែលអាចបណ្តាលឲ្យវាខុសពីសេចក្តីណែនាំ បង្កើតមាតិកាដែលមានគ្រោះថ្នាក់
ធ្វើឲ្យមានការចូលប្រើដោយគ្មានការអនុញ្ញាត ឬប៉ះពាល់ដល់ការមាតិកាសំខាន់ៗ។ ទោះបីមានបច្ចេកទេសដូចជា Retrieval-Augmented Generation (RAG) និង Fine-tuning ដែលមានគោលបំណងធ្វើឲ្យលទ្ធផលរបស់ LLM មានភាពពាក់ព័ន្ធ និងត្រឹមត្រូវកាន់តែច្រើនក៏ដោយ ក៏ការស្រាវជ្រាវបង្ហាញថា វានៅតែមិនអាចការពារពី Prompt Injection បានទាំងស្រុងនោះទេ។

ទោះបីជា Prompt Injection និង Jailbreaking ជាគំនិតដែលពាក់ព័ន្ធនឹងសុវត្ថិភាព LLM ក៏ដោយ ក៏វាមានការប្រើប្រាស់ជំនួសគ្នានៅពេលខ្លះដែរ។ Prompt Injection គឺជាវិធីសាស្ត្រមួយក្នុងការបញ្ជៀសឲ្យម៉ូដែលឆ្លើយតបខុសពីបំណង ដោយប្រើការបញ្ចូលពិសេសៗដើម្បីផ្លាស់ប្តូរការប្រព្រឹត្តិរបស់វា ហើយវាអាចរួមបញ្ចូលការបំបែកប្រព័ន្ធសុវត្ថិភាពផងដែរ។ Jailbreaking ជាប្រភេទមួយនៃ Prompt Injection ដែលអ្នកវាយប្រហារបញ្ចូល prompt ដែលធ្វើឲ្យម៉ូដែលមិនអនុវត្តន៍តាមបច្ចេកទេសសុវត្ថិភាពទាំងស្រុង។ អ្នកអភិវឌ្ឍអាចបង្កើតវិធានការការពារ ដោយដាក់ការកំណត់នៅក្នុង system prompts និងក្នុងការដោះស្រាយការបញ្ចូលពីអ្នកប្រើប្រាស់ ដើម្បីជួយបន្ថយហានិភ័យនៃការវាយប្រហារ Prompt Injection។ ប៉ុន្តែការការពារ Jailbreaking ឲ្យមានប្រសិទ្ធភាព ត្រូវការការធ្វើបច្ចុប្បន្នភាពប្រព័ន្ធបណ្តុះបណ្តាល និងយុទ្ធសាស្ត្រសុវត្ថិភាពរបស់ម៉ូឌែលជាប្រចាំ។

## ប្រភេទនៃភាពងាយរងគ្រោះដោយសារ Prompt Injection

### Prompt Injection ដោយផ្ទាល់

Prompt Injection ដោយផ្ទាល់ (Direct Prompt Injection) កើតឡើងនៅពេលដែលអត្ថបទបញ្ចូល (prompt) របស់អ្នកប្រើប្រាស់ ប៉ះពាល់ដោយផ្ទាល់ដល់របៀបធ្វើការ (behavior) របស់ម៉ូដែល បង្កើតឲ្យមានលទ្ធផលខុសពីបំណង ឬមិនបានរំពឹងទុក។ ពាក្យបញ្ចូលអាចជាការបញ្ចូលដោយចេតនា (ឧ.​​​​ មានគោលបំណងអាក្រក់ បង្កើតពាក្យស្នើជាចេតនា ដើម្បីប្រើប្រាស់ម៉ូឌែល) ឬដោយអចេតនា (ឧ. អ្នកប្រើប្រាស់ផ្តល់ពាក្យស្នើដោយចៃដន្យដែលបង្កឲ្យមានបញ្ហាដោយមិនបានរំពឹងទុក)។

### Prompt Injection ដោយប្រយោល

Prompt Injection ដោយប្រយោល (Indirect Prompt Injection) កើតឡើងនៅពេលម៉ូដែល LLM ទទួលយកទិន្នន័យពីប្រភពខាងក្រៅ ដូចជាគេហទំព័រ ឬឯកសារ។ ទិន្នន័យក្នុងប្រភពខាងក្រៅនោះអាចមានខ្លឹមសារដែលពេលម៉ូដែលបកស្រាយនោះ នឹងធ្វើឲ្យផ្លាស់ប្តូររបៀបធ្វើការរបស់វាដោយមិនបានរំពឹងទុក ឬមិនចង់ឲ្យកើតឡើង។
ដូចទៅនឹងការបញ្ចូលសំណើដោយផ្ទាល់ ការបញ្ចូលសំណើប្រយោលនេះអាចកើតឡើងដោយចេតនា ឬដោយអចេតនាបានផងដែរ។

ភាពធ្ងន់ធ្ងរ និងលក្ខណៈនៃផលប៉ះពាល់ ដែលកើតឡើងដោយសារការវាយប្រហារបែប prompt injection បានជោគជ័យ អាចខុសគ្នាយ៉ាងខ្លាំង​ ដោយអាស្រ័យទៅលើស្ថានភាពដែលម៉ូឌែលនោះត្រូវបានប្រើប្រាស់ និងរចនាសម្ព័ន្ធ (architecture) របស់វា។ ជាទូទៅ ពេលមានការវាយប្រហារបែបនេះ ម៉ូដែលអាចបង្កើតលទ្ធផលមិនបានរំពឹងទុកជាច្រើនប្រភេទ មានដូចជា៖

- បង្ហាញព័ត៌មានសម្ងាត់
- បង្ហាញព័ត៌មានសម្ងាត់អំពីរចនាសម្ព័ន្ធរបស់ប្រព័ន្ធ AI​ ឬ system prompts
- ការបំលែងខ្លឹមសារដែលធ្វើឲ្យការឆ្លើយតបមិនត្រឹមត្រូវ ឬលំអៀង
- ផ្ដល់ឱ្យមានការចូលប្រើមុខងាររបស់ម៉ូដែល LLM ដោយគ្មានការអនុញ្ញាត
- ដំណើរការពាក្យបញ្ជាឬសំណើដែលមិនបានកំណត់នៅលើប្រព័ន្ធដែលភ្ជាប់ជាមួយ
- ការជ្រៀតចូលបំផ្លាញដល់ដំណើរការនៃការធ្វើសេចក្ដីសម្រេចសំខាន់ៗ

ការកើនឡើងនៃបច្ចេកវិទ្យា AI បែប Multimodal ដែលអាចដំណើរការទិន្នន័យច្រើនប្រភេទក្នុងពេលតែមួយ បាននាំមកនូវហានិភ័យបែប Prompt Injection បែបថ្មី។ អ្នកដែលមានបំណងអាក្រក់អាចប្រើប្រភេទទិន្នន័យផ្សេងៗទាំងនេះទៅប្រើប្រាស់ក្នុងការវាយប្រហារ ដូចជា លាក់សេចក្ដីណែនាំនៅក្នុងរូបភាពដែលភ្ជាប់ជាមួយអត្ថបទធម្មតា។ ភាពស្មុគស្មាញនៃប្រព័ន្ធទាំងនេះ បានធ្វើឲ្យមានគ្រោះថ្នាក់ច្រើនក្នុងការត្រូវវាយប្រហារ។ ម៉ូឌែល Multimodal ក៏អាចងាយរងការវាយប្រហារបែបថ្មីៗ ដែលប្រើប្រាស់ទិន្នន័យចម្រុះ (cross-modal) ដែលពិបាកក្នុងការរកឃើញ និងទប់ស្កាត់ដោយបច្ចេកវិទ្យាបច្ចុប្បន្ន។ ដូច្នេះ ការការពារដែលត្រូវបានរចនាពិសេសសម្រាប់ម៉ូឌែល Multimodal ហើយមានសមត្ថភាពខ្ពស់ គឺជាផ្នែកសំខាន់សម្រាប់ការស្រាវជ្រាវ និងអភិវឌ្ឍន៍បន្ថែម។

## យុទ្ធសាស្ត្រការពារ និងបន្ថយផលប៉ះពាល់

ការវាយប្រហារបែប Prompt Injection អាចកើតមានបាន ព្រោះ Generative AI មានលក្ខណៈដើមដែលងាយរងគ្រោះ។ ដោយសារតែភាពចៃដន្យ (stochastic) ជាមូលដ្ឋាននៃវិធីដំណើរការរបស់ម៉ូឌែល មិនមានការបញ្ជាក់ច្បាស់ថា តើមានវិធីការពារណាដែលអាចទុកចិត្តបានទាំងស្រុងសម្រាប់ការការពារប្រឆាំង Prompt Injection ឬទេ។ ទោះជាយ៉ាងណា វិធានការខាងក្រោមអាចជួយបន្ថយឥទ្ធិពលនៃការវាយប្រហារបែបនេះបាន៖

### ១. រឹតបន្តឹងសកម្មភាពរបស់ម៉ូឌែល

ផ្តល់ការណែនាំជាក់លាក់អំពីតួនាទី សមត្ថភាព និងដែនកំណត់របស់ម៉ូឌែល នៅក្នុង system prompt។ អនុវត្តការប្រកាន់ខ្ជាប់បរិបទយ៉ាងតឹងរ៉ឹង កំណត់ការឆ្លើយតបចំពោះកិច្ចការ ឬប្រធានបទជាក់លាក់ ហើយណែនាំម៉ូឌែលមិនឲ្យយកចិត្តទុកដាក់ចំពោះការប្រែប្រួលឬផ្លាស់ប្តូរការណែនាំសំខាន់ៗ។

### ២. កំណត់ និងផ្ទៀងផ្ទាត់ទ្រង់ទ្រាយលទ្ធផលដែលរំពឹងទុក

បញ្ជាក់អំពីទម្រង់នៃលទ្ធផលឲ្យបានច្បាស់លាស់ ស្នើសុំអោយបង្ហាញហេតុផលលម្អិត និងប្រភពយោង ហើយប្រើកូដដែលអាចត្រួតពិនិត្យបាន ដើម្បីផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវនៃទម្រង់ទាំងនេះ។

### ៣. អនុវត្តការធ្វើចម្រាញ់លើទិន្នន័យបញ្ចូល និងលទ្ធផលចេញ

កំណត់ប្រភេទមាតិកាដែលពិបាកគ្រប់គ្រង ហើយបង្កើតច្បាប់សម្រាប់សម្គាល់ និងដោះស្រាយមាតិកាប្រភេទនោះ។ ប្រើ​ semantic-filters និង string-checking ដើម្បីស្កេនរកមាតិកាដែលមិនត្រូវបានអនុញ្ញាត។ វាយតម្លៃចម្លើយដោយប្រើ RAG Triad៖ វាយតម្លៃភាពពាក់ព័ន្ធនៃបរិបទ ការបង្ហាញព័ត៌មានផ្អែកលើប្រភព និងភាពពាក់ព័ន្ធរវាងសំណួរ/ចម្លើយ ដើម្បីកំណត់សម្គាល់លទ្ធផលដែលគ្រោះថ្នាក់បាន។

### ៤. អនុវត្តការគ្រប់គ្រងសិទ្ធិ្ធ និងកំណត់ការចូលប្រើតិចបំផុត

ផ្តល់ឲ្យកម្មវិធីនូវ API token ផ្ទាល់ខ្លួនសម្រាប់មុខងារដែលអាចបន្ថែមបាន ហើយគ្រប់គ្រងមុខងារទាំងនេះតាមកូដជំនួសការផ្តល់ទៅម៉ូឌែល។ កំណត់សិទ្ធិចូលប្រើរបស់ម៉ូឌែលឲ្យតិចបំផុតតាមតម្រូវការសម្រាប់ការប្រតិបត្តិការដែលបានកំណត់។

### ៥.ទាមទារការអនុម័តពីមនុស្សសម្រាប់សកម្មភាពដែលមានហានិភ័យខ្ពស់

អនុវត្តការឱ្យមានការត្រួតពិនិត្យដោយមនុស្សជាមុន ក្នុងដំណើរការសម្រាប់សកម្មភាពដែលមានសិទ្ធិពិសេស ដើម្បីទប់ស្កាត់សកម្មភាពដែលមិនទាន់មានការអនុញ្ញាត។

### ៦. បំបែក និងកំណត់សម្គាល់មាតិកាប្រភពខាងក្រៅ

បំបែក និងកត់សម្គាល់ឲ្យបានច្បាស់លាស់លើមាតិកាដែលមិនទុកចិត្ត ដើម្បីកំណត់ឥទ្ធិពលរបស់វាលើការបញ្ចូលរបស់អ្នកប្រើប្រាស់។

### ៧. ធ្វើតេស្តប្រឆាំង និងត្រៀមសម្តែងវាយប្រហារ

ធ្វើតេស្តការចូលវាយប្រហារនិងកែសម្រួលសកម្មភាពវាយប្រហារជាប្រចាំ ដោយចាត់ទុកម៉ូឌែលជាអ្នកប្រើដែលមិនទុកចិត្ត ដើម្បីសាកល្បងប្រសិទ្ធភាពនៃកម្រិតនៃការទុកចិត្ត និងការគ្រប់គ្រងសិទ្ធិចូលប្រើប្រាស់។

## ឧទាហរណ៍សេណារីយោនៃការវាយប្រហារ

### សេណារីយូ #១៖ Injection​ ដោយផ្ទាល់

អ្នកវាយប្រហារបានបញ្ចូលសំណើ (prompt) មួយទៅក្នុងប្រព័ន្ធជជែកជាមួយអតិថិជន (chatbot) ដោយបញ្ជាឱ្យវាមិនអើពើនឹងការណែនាំមុនៗ បន្តរកមើលទិន្នន័យឯកជន និងផ្ញើអ៊ីមែល។ វាបានបណ្តាលឱ្យមានការចូលប្រើប្រាស់ដោយគ្មានការអនុញ្ញាត និងបង្កើនសិទ្ធិដែលគ្រោះថ្នាក់។

### សេណារីយូ #២៖ Injection បែបប្រយោល

អ្នកប្រើប្រាស់ម្នាក់ប្រើ LLM ដើម្បីសង្ខេបគេហទំព័រមួយដែលមានសេចក្ដីណែនាំលាក់ខ្លួន។ សេចក្ដីណែនាំនោះបណ្តាលឲ្យ LLM បញ្ចូលរូបភាពមួយដែលភ្ជាប់តំណទៅកាន់ URL ដែលបណ្តាលឲ្យមានការចេញព័ត៌មានសម្ងាត់ពីការសន្ទនាឯកជន។

### សេណារីយូ #៣៖ Injection​ ដោយអចេតនា

ក្រុមហ៊ុនមួយដាក់សេចក្ដីណែនាំក្នុងការពិពណ៌នាការងារ ដើម្បីសម្គាល់ពាក្យស្នើសុំដែលបង្កើតដោយ AI។ បេក្ខជនម្នាក់ដែលមិនដឹងអំពីសេចក្ដីណែនាំនេះ បានប្រើ LLM ដើម្បីបង្កើនប្រសិទ្ធភាពប្រវត្តិរូបរបស់ខ្លួន ហើយដោយអចេតនា បានបង្កើតឱ្យប្រព័ន្ធរកឃើញថា ប្រវត្តិរូបនោះបង្កើតដោយ AI។

### សេណារីយូ #៤៖ ឥទ្ធិពលលើម៉ូឌែលដោយចេតនា (Intentional Model Influence)

អ្នកវាយប្រហារម្នាក់ កែប្រែឯកសារមួយនៅក្នុង repository ដែលប្រើដោយកម្មវិធី Retrieval-Augmented Generation (RAG)។ នៅពេលដែលសំណួររបស់អ្នកប្រើប្រាស់ទាញយកមាតិកាដែលបានកែប្រែ វាបញ្ជូនសេចក្ដីណែនាំប្លែកៗដែលបណ្តាលឲ្យ LLM បង្ហាញលទ្ធផលខុសឆ្គង ឬបំប្លែងការពិត។

### សេណារីយូ #៥៖ Injection កូដ

អ្នកវាយប្រហារម្នាក់ អនុវត្តការប្រើប្រាស់ភាពងាយរងគ្រោះ (CVE-2024-5184) នៅក្នុងជំនួយការអ៊ីមែលដែលដំណើរការដោយ LLM ដើម្បីដាក់បញ្ចូលសំណើដែលមានបញ្ហា។ វាធ្វើឲ្យអាចចូលប្រើព័ត៌មានសម្ងាត់ និងបំលែងខ្លឹមសារអ៊ីមែលបាន។

### សេណារីយូ #៦៖ ការបំបែក Payload

អ្នកវាយប្រហារម្នាក់បញ្ចូលប្រវត្តិរូបមួយដែលមាន prompt មានបញ្ហាហើយបែងចែកជាច្រើនផ្នែកផ្សេងៗ។ នៅពេល LLM ត្រូវបានប្រើសម្រាប់វាយតម្លៃបេក្ខជន ពាក្យបញ្ចូលដែលបំបែកនោះត្រូវបានបញ្ចូលរួមគ្នា ហើយបំផ្លាញការឆ្លើយតបរបស់ម៉ូឌែល ដោយធ្វើឲ្យ LLM ផ្តល់អនុសាសន៍វិជ្ជមាន ទោះបីខ្លឹមសារពិតប្រាកដនៃប្រវត្តិរូបមិនសមស្របក៏ដោយ។

### សេណារីយូ #៧៖ Multimodal Injection

អ្នកវាយប្រហារបញ្ចូលសំណើដែលមានគោលបំណងអាក្រក់ (malicious prompt) ទុកក្នុងរូបភាពមួយ ដែលមើលទៅដូចជាអត្ថបទធម្មតា។ នៅពេល AI ដែលអាចអានទាំងរូបភាពនិងអត្ថបទ (multimodal AI) ប្រើទិន្នន័យទាំងពីរនេះក្នុងពេលតែមួយ prompt​ ដែលលាក់ក្នុងរូបភាពនោះអាចបង្ខំឲ្យម៉ូឌែលបំពេញសកម្មភាពដែលមិនត្រូវ ដូចជាបង្ហាញព័ត៌មានសម្ងាត់ ឬអនុវត្តអ្វីៗដោយគ្មានការអនុញ្ញាត។

### សេណារីយូ #៨៖ បច្ចេកទេសបន្ថែមខាងចុង (Adversarial Suffix)

អ្នកវាយប្រហារបន្ថែមអក្សរទៅក្នុង prompt ទោះបីវាមើលទៅគ្មានអត្ថន័យក៏ដោយ ប៉ុន្តែវាអាចបញ្ឆោត LLM ឲ្យមិនគោរពច្បាប់សុវត្ថិភាព ហើយបង្កើតអត្ថបទដែលមានគ្រោះថ្នាក់ ឬមិនត្រូវបានអនុញ្ញាត។

### សេណារីយូ #៩៖ ការវាយប្រហារច្រើនភាសា​ ឬប្រើភាសាចម្រុះ

អ្នកវាយប្រហារប្រើភាសាច្រើន ឬការបំបាំងសំណើដែលមានគោលបំណងអាក្រក់ដោយបំលែងវាជារូបរាងផ្សេងៗ (ឧ. Base64, emoji, ឬតួអក្សរពិសេស)។ ដើម្បីជៀសវាងការស្វែងរក ហើយបំលែងអាកប្បកិរិយារបស់ LLM។
