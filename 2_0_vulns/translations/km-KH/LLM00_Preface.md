# លិខិតពីប្រធានគម្រោង

គម្រោង OWASP Top 10 សម្រាប់កម្មវិធីម៉ូដែលភាសាធំ (Large Language Model Applications) បានចាប់ផ្ដើមឡើងនៅក្នុងឆ្នាំ២០២៣ ក្នុងនាមជាការខិតខំប្រឹងប្រែងរួមគ្នាដោយសហគមន៍ ដើម្បីគូសបញ្ជាក់ និងដោះស្រាយបញ្ហាសុវត្ថិភាពដែលពាក់ព័ន្ធជាពិសេសទៅនឹងកម្មវិធីបញ្ញាសិប្បនិម្មិត (AI)។ ចាប់តាំងពីពេលនោះមក បច្ចេកវិទ្យានេះបានបន្តរីករាលដាលនៅក្នុងវិស័យឧស្សាហកម្ម និងកម្មវិធីនានា ហើយហានិភ័យដែលពាក់ព័ន្ធក៏បានកើនឡើងដូចគ្នាដែរ។ ខណៈដែលម៉ូដែលភាសាធំ (LLM) កំពុងត្រូវបានដាក់បញ្ចូលកាន់តែជ្រៅទៅក្នុងប្រតិបត្តិការគ្រប់យ៉ាង ចាប់ពីអន្តរកម្មជាមួយអតិថិជន រហូតដល់ប្រតិបត្តិការផ្ទៃក្នុង, ក្រុមអ្នកអភិវឌ្ឍ និងអ្នកជំនាញផ្នែកសុវត្ថិភាពកំពុងតែរកឃើញនូវចន្លោះប្រហោងថ្មីៗ—ព្រមទាំងវិធីសាស្ត្រដើម្បីទប់ទល់នឹងបញ្ហាទាំងនោះ។

បញ្ជីឆ្នាំ២០២៣ បានទទួលជោគជ័យយ៉ាងធំធេងក្នុងការលើកកម្ពស់ការយល់ដឹង និងការកសាងមូលដ្ឋានគ្រឹះសម្រាប់ការប្រើប្រាស់ LLM ប្រកបដោយសុវត្ថិភាព ប៉ុន្តែយើងបានរៀនសូត្រកាន់តែច្រើនបន្ថែមទៀតចាប់តាំងពីពេលនោះមក។ នៅក្នុងកំណែថ្មីឆ្នាំ២០២៥ នេះ យើងបានធ្វើការជាមួយក្រុមអ្នកចូលរួមចំណែកដែលមានចំនួនកាន់តែច្រើន និងចម្រុះមកពីជុំវិញពិភពលោក ដែលពួកគាត់ទាំងអស់បានជួយរៀបចំបញ្ជីនេះឡើង។ ដំណើរការនេះរួមមាន វគ្គពិភាក្សាផ្លាស់ប្តូរគំនិត ការបោះឆ្នោត និងការទទួលមតិកែលម្អជាក់ស្ដែងពីអ្នកជំនាញដែលកំពុងធ្វើការយ៉ាងសកម្មក្នុងវិស័យសុវត្ថិភាពកម្មវិធី LLM មិនថាតាមរយៈការចូលរួមចំណែកដោយផ្ទាល់ ឬការសម្រិតសម្រាំងខ្លឹមសារតាមរយៈមតិកែលម្អនោះទេ។ សំឡេងនីមួយៗមានសារៈសំខាន់ណាស់ក្នុងការធ្វើឱ្យការចេញផ្សាយថ្មីនេះមានភាពគ្រប់ជ្រុងជ្រោយ និងអាចយកទៅអនុវត្តបានជាក់ស្ដែងតាមដែលអាចធ្វើទៅបាន។

## តើមានអ្វីថ្មីនៅក្នុងបញ្ជី Top 10 ឆ្នាំ២០២៥

បញ្ជីឆ្នាំ២០២៥ ឆ្លុះបញ្ចាំងពីការយល់ដឹងកាន់តែច្បាស់អំពីហានិភ័យដែលមានស្រាប់ និងបង្ហាញពីបច្ចុប្បន្នភាពសំខាន់ៗអំពីរបៀបដែល LLM ត្រូវបានប្រើប្រាស់នៅក្នុងកម្មវិធីជាក់ស្ដែងនាពេលបច្ចុប្បន្ន។ ជាឧទាហរណ៍ ចំណុច **Unbounded Consumption (ការប្រើប្រាស់ធនធានគ្មានដែនកំណត់)** បានពង្រីកបន្ថែមពីលើហានិភ័យដែលពីមុនហៅថា Denial of Service (ការបដិសេធសេវាកម្ម) ដោយរួមបញ្ចូលទាំងហានិភ័យជុំវិញការគ្រប់គ្រងធនធាន និងការចំណាយដែលមិនបានរំពឹងទុក—ដែលនេះជាបញ្ហាចោទដ៏ធំមួយនៅក្នុងការដាក់ឱ្យប្រើប្រាស់ LLM ក្នុងទ្រង់ទ្រាយធំ។

ចំណុចដែលទាក់ទងនឹង **Vector and Embeddings** គឺជាការឆ្លើយតបទៅនឹងសំណើរបស់សហគមន៍ដែលចង់បានការណែនាំអំពីការពង្រឹងសុវត្ថិភាពនៃបច្ចេកទេស Retrieval-Augmented Generation (RAG) និងវិធីសាស្ត្រផ្សេងទៀតដែលផ្អែកលើ embedding ដែលបច្ចុប្បន្ននេះជាមូលដ្ឋានគ្រឹះក្នុងការធ្វើឱ្យលទ្ធផលរបស់ម៉ូដែល​មានមូលដ្ឋានច្បាស់លាស់។

យើងក៏បានបន្ថែមចំណុច **System Prompt Leakage (ការលេចធ្លាយសារបញ្ជាប្រព័ន្ធ)** ដើម្បីដោះស្រាយបញ្ហានៅក្នុងផ្នែកមួយដែលមានការវាយលុកជាក់ស្ដែង ហើយត្រូវបានស្នើសុំយ៉ាងច្រើនពីសហគមន៍។ កម្មវិធីជាច្រើនបានសន្មតថា prompt ត្រូវបានរក្សាទុកដោយឯកเทศ និងមានសុវត្ថិភាព ប៉ុន្តែឧប្បត្តិហេតុថ្មីៗនេះបានបង្ហាញថា អ្នកអភិវឌ្ឍមិនអាចសន្មតដោយសុវត្ថិភាពថាព័ត៌មាននៅក្នុង prompt ទាំងនេះនឹងនៅតែជាការសម្ងាត់បានទៀតទេ។

ចំណុច **Excessive Agency (សិទ្ធិធ្វើសកម្មភាពលើសកម្រិត)** ត្រូវបានពង្រីកបន្ថែម ដោយសារតែការកើនឡើងនៃការប្រើប្រាស់ស្ថាបត្យកម្មបែប agentic ដែលអាចផ្តល់ឱ្យ LLM នូវស្វ័យភាពកាន់តែច្រើន។ នៅពេលដែល LLM ដើរតួជា agent ឬស្ថិតនៅក្នុងការកំណត់ជាមួយ plug-in, ការអនុញ្ញាតដែលគ្មានការត្រួតពិនិត្យអាចនាំទៅរកសកម្មភាពដែលមិនបានគ្រោងទុក ឬប្រកបដោយគ្រោះថ្នាក់ ដែលធ្វើឱ្យចំណុចនេះកាន់តែមានសារៈសំខាន់ជាងពេលណាៗទាំងអស់។

## ដំណើរឆ្ពោះទៅមុខ

ដូចទៅនឹងបច្ចេកវិទ្យាដែរ បញ្ជីនេះគឺជាសមិទ្ធផលដែលកើតចេញពីការយល់ដឹង និងបទពិសោធន៍របស់សហគមន៍ប្រភពកូដចំហ (open-source community)។ វាត្រូវបានរៀបចំឡើងដោយមានការចូលរួមចំណែកពីអ្នកអភិវឌ្ឍ អ្នកវិទ្យាសាស្ត្រទិន្នន័យ និងអ្នកជំនាញផ្នែកសុវត្ថិភាពមកពីគ្រប់វិស័យ ដែលទាំងអស់នេះសុទ្ធតែប្តេជ្ញាចិត្តក្នុងការកសាងកម្មវិធី AI ដែលមានសុវត្ថិភាពជាងមុន។ យើងមានមោទនភាពក្នុងការចែករំលែកកំណែឆ្នាំ២០២៥ នេះជាមួយអ្នក ហើយយើងសង្ឃឹមថាវានឹងផ្តល់ឱ្យអ្នកនូវឧបករណ៍ និងចំណេះដឹងដើម្បីការពារ LLM ប្រកបដោយប្រសិទ្ធភាព។

សូមអរគុណដល់អ្នកគ្រប់គ្នាដែលបានជួយធ្វើឱ្យគម្រោងនេះកើតឡើង និងអ្នកដែលបន្តប្រើប្រាស់ និងកែលម្អវា។ យើងពិតជាមានអំណរគុណដែលបានក្លាយជាផ្នែកមួយនៃការងារនេះជាមួយអ្នក។
