## LLM03:2025 ខ្សែសង្វាក់ផ្គត់ផ្គង់(Supply Chain)

### ការពិពណ៌នា

ខ្សែសង្វាក់ផ្គត់ផ្គង់ LLM មានការប្រឈមជាមួយនឹងភាពងាយរងគ្រោះ (vulnerabilities) ផ្សេងៗ ដែលអាចប៉ះពាល់ ដល់ភាពត្រឹមត្រូវ នៃទិន្នន័យបណ្តុះបណ្តាល, ម៉ូដែល, និងវេទិកាដាក់ឲ្យប្រើ។ គ្រោះថ្នាក់ទាំងនេះអាចបណ្តាលឲ្យមានលទ្ធផលលំអៀង, ការរំលោភសុវត្ថិភាព, ឬការបរាជ័យប្រព័ន្ធ។ ខណៈពេលដែលភាពងាយរងគ្រោះក្នុងកម្មវិធីសូហ្វវែរទូទៅ (traditional software vulnerabilities) ផ្តោតលើបញ្ហាដូចជា កំហុសកូដ និងការពឹងផ្អែក, ក្នុង ML គ្រោះថ្នាក់ក៏រីករាលដាលទៅដល់ ម៉ូដែលដែលត្រៀមជាមុនដោយភាគីទីបី (third-party pre-trained models) និងទិន្នន័យផងដែរ។

ធាតុខាងក្រៅទាំងនេះអាចត្រូវបានបំលែង ឬប៉ះពាល់ ដោយការបំពាន ឬការបំពុលទិន្នន័យ។

ការបង្កើត LLMs គឺជាការងារពិសេសដែលភាគច្រើនពឹងផ្អែកលើ ម៉ូដែលពីភាគីទីបី(third-party models)។ ការកើនឡើងនៃ open-access LLMs និងវិធីសាស្ត្រកែលម្អម៉ូដែល ថ្មីៗដូចជា "LoRA" (Low-Rank Adaptation) និង "PEFT" (Parameter-Efficient Fine-Tuning) ជាពិសេសលើវេទិកាដូចជា Hugging Face បាននាំមកនូវហានិភ័យថ្មីៗ​​ ក្នុងខ្សែសង្វាក់ផ្គត់ផ្គង់។ ចុងក្រោយ ការលេចឡើងនៃ on-device LLMs ក៏បានបង្កើនផ្ទៃវាយប្រហារ និងហានិភ័យ ខ្សែសង្វាក់ផ្គត់ផ្គង់ សម្រាប់កម្មវិធី​ LLM ផងដែរ។

ហានិភ័យខ្លះៗដែលបានពិភាក្សានៅទីនេះ ក៏ត្រូវបានពិភាក្សានៅក្នុង "LLM04 ទិន្នន័យ និង​ ការបំពុលម៉ូដែល" ផងដែរ។ កំណត់ត្រានេះ ផ្តោតលើផ្នែកខ្សែសង្វាក់ផ្គត់ផ្គង់ នៃហានិភ័យទាំងនេះ។
គំរូគ្រោះថ្នាក់សាមញ្ញអាចរកបាន [ទីនេះ](https://github.com/jsotiro/ThreatModels/blob/main/LLM%20Threats-LLM%20Supply%20Chain.png)។

### ឧទាហរណ៍ទូទៅនៃហានិភ័យ

#### ១. ភាពងាយរងគ្រោះនៃកញ្ចប់ពីភាគីទីបីបែបបុរាណ (Traditional Third-party Package Vulnerabilities)

ដូចជាសមាសធាតុដែលហួសសម័យ (outdated) ឬលែងប្រើ (deprecated) ដែលអ្នកវាយប្រហារអាចប្រើប្រាស់ដើម្បីបំពាន កម្មវិធី LLM​។ នេះគឺស្រដៀងទៅនឹង "A06:2021 – Vulnerable and Outdated Components" ជាមួយនឹងហានិភ័យកើនឡើងនៅពេលដែលសមាសធាតុត្រូវបានប្រើក្នុងអំឡុងពេលអភិវឌ្ឍន៍ម៉ូដែល (model development) ឬ fine-tuning។
(តំណភ្ជាប់យោង៖ [A06:2021 – Vulnerable and Outdated Components](https://owasp.org/Top10/A06_2021-Vulnerable_and_Outdated_Components/))

##### ២. ហានិភ័យអាជ្ញាប័ណ្ណ (Licensing Risks)

ការអភិវឌ្ឍន៍ AI ជាញឹកញាប់ត្រូវពាក់ព័ន្ធនឹង software និង dataset licenses ផ្សេងៗ ដែលអាចបង្កើតហានិភ័យ ប្រសិនបើមិនបានគ្រប់គ្រងឲ្យបានត្រឹមត្រូវ។ Open-source និង proprietary licenses ផ្តល់លក្ខខណ្ឌផ្លូវច្បាប់ ផ្សេងៗគ្នា។ Dataset licenses អាចមានការកំណត់លើការប្រើប្រាស់, ការចែកចាយ, ឬការជួញដូរ។

#### ៣. ម៉ូដែលដែលហួសសម័យ ឬលែងប្រើ (Outdated or Deprecated Models)

ការប្រើ ម៉ូដែលចាស់ ឬម៉ូដែលដែលត្រូវបានបោះបង់ ហើយមិនទទួលបានការថែទាំ អាចនាំឲ្យមានបញ្ហាផ្នែកសុវត្ថិភាព។

#### ៤. ម៉ូដែលដែលបានបណ្តុះបណ្តាលជាមុនដែលងាយរងគ្រោះ (Vulnerable Pre-Trained Model)

ម៉ូដែលទាំងនេះជាប្រភេទ binary black boxes ហើយផ្ទុយពី open source, ការត្រួតពិនិត្យស្ថិតិ​ អាចផ្តល់ការធានាសុវត្ថិភាពបានតិចតួចប៉ុណ្ណោះ។ ម៉ូដែល Pre-Trained ដែលងាយរងគ្រោះ អាចមាន biases ដែលលាក់ខ្លួន, backdoors, ឬ មុខងារប៉ះពាល់ផ្សេងៗ ដែលមិនត្រូវបានរកឃើញតាមការវាយតម្លៃសុវត្ថិភាព នៃ ឃ្លាំងម៉ូដែល។​ ម៉ូដែលងាយរងគ្រោះអាចត្រូវបានបង្កើត ដោយទាំងសំណុំទិន្នន័យ ដែលបំពុល និង ការបំពានលើម៉ូដែលដោយផ្ទាល់ ប្រើប្រាស់បច្ចេកទេសដូចជា ROME ដែលគេហៅថា lobotomisation។

#### ៥. ប្រភពម៉ូដែលខ្សោយ (Weak Model Provenance)

បច្ចុប្បន្ននេះ មិនមានការធានាប្រភពដ៏រឹងមាំសម្រាប់ម៉ូដែលដែលបានផ្សាយចេញទេ។ កាតម៉ូដែល និងឯកសារភ្ជាប់ គ្រាន់តែផ្តល់ព័ត៌មានអំពីម៉ូដែល និងអនុញ្ញាតឲ្យអ្នកប្រើពឹងផ្អែក តែពួកគេមិនមានការធានាអំពីប្រភពដើមនៃម៉ូដែលឡើយ។ អ្នកវាយប្រហារអាចលួចគណនីអ្នកផ្គត់ផ្គង់នៅលើ ឃ្លាំងម៉ូដែល ឬបង្កើតគណនីស្រដៀង ហើយបន្សំជាមួយនឹងបច្ចេកទេស វិស្វកម្មបណ្ដាញសង្គម (social engineering)ដើម្បីវាយប្រហារលើខ្សែសង្វាក់ផ្គត់ផ្គង់នៃកម្មវិធី LLM។

#### ៦. អាដាប់ធ័រ LoRA ដែលងាយរងគ្រោះ

LoRA គឺជាវិធីសាស្ត្រកែលម្អម៉ូដែល (fine-tuning) ដែលពេញនិយមមួយ ដោយបន្ថែមស្រទាប់ដែលបានបណ្តុះបណ្តាលរួចទៅលើម៉ូដែល LLM ដែលមានស្រាប់។ វិធីសាស្ត្រនេះជួយបង្កើនប្រសិទ្ធភាព ប៉ុន្តែបង្កើតហានិភ័យថ្មីៗ ដោយ LoRA adapter ដែលមានគំនិតអាក្រក់អាចបំផ្លាញភាពត្រឹមត្រូវ និងសុវត្ថិភាពរបស់ម៉ូដែលមូលដ្ឋាន។ ហានិភ័យនេះអាចកើតឡើងទាំងក្នុងបរិស្ថានបញ្ចូលម៉ូដែលរួម (collaborative model merge) និងការប្រើប្រាស់ LoRA នៅលើវេទិកាដាក់ឲ្យប្រើដូចជា vLLM និង OpenLLM ដែលអាដាប់ធ័រអាចត្រូវបានទាញយក និងដាក់បន្ថែមទៅលើម៉ូដែលដែលបានដាក់ឲ្យប្រើ។

### ៧. ការបំពានតាមដំណើរការអភិវឌ្ឍន៍រួម

ការបញ្ចូលម៉ូដែលរួម និងសេវាកម្មដោះស្រាយម៉ូដែល (ដូចជា ការបម្លែងទ្រង់ទ្រាយ) ដែលដំណើរការនៅបរិស្ថានរួម អាចត្រូវបានប្រើប្រាស់ដើម្បីបញ្ចូលភាពងាយរងគ្រោះទៅក្នុងម៉ូដែលដែលចែករំលែក។ ការបញ្ចូលម៉ូដែលរួមគឺពេញនិយមនៅលើ Hugging Face ដែលម៉ូដែលបញ្ចូលរួមកំពុងឈរកំពូលក្នុង OpenLLM leaderboard ហើយអាចត្រូវបានប្រើប្រាស់ដើម្បីជៀសវាងការត្រួតពិនិត្យ។ ដូចគ្នានេះផងដែរ សេវាកម្មដូចជា កម្មវិធីជជែកដោយស្វ័យប្រវត្តិ ត្រូវបានបង្ហាញថាងាយរងការបំពាន និងអាចបញ្ចូលកូដអាក្រក់ទៅក្នុងម៉ូដែល។

### ៨. ភាពងាយរងគ្រោះខ្សែសង្វាក់ផ្គត់ផ្គង់ LLM នៅលើឧបករណ៍

ម៉ូដែល LLM នៅលើឧបករណ៍ បង្កើនផ្ទៃវាយប្រហារខ្សែសង្វាក់ផ្គត់ផ្គង់ ដោយមានដំណើរការផលិតដែលអាចត្រូវបានបំពាន និងការប្រើប្រាស់ភាពងាយរងគ្រោះរបស់ប្រព័ន្ធប្រតិបត្តិការ ឬ firmware ដើម្បីបំពានម៉ូដែល។ អ្នកវាយប្រហារអាចធ្វើការវិភាគបញ្ច្រាស (reverse engineer) និងកែប្រែកម្មវិធីដោយបន្ថែមម៉ូដែលដែលបានបំពាន។។

### ៩. គោលការណ៍ T&Cs និងភាពឯកជនទិន្នន័យមិនច្បាស់លាស់

គោលការណ៍ T&Cs និងភាពឯកជនទិន្នន័យមិនច្បាស់លាស់របស់អ្នកបើកប្រតិបត្តិម៉ូដែល នាំឲ្យទិន្នន័យសំខាន់របស់កម្មវិធីត្រូវបានប្រើសម្រាប់បណ្តុះបណ្តាលម៉ូដែល និងបង្ហាញព័ត៌មានសំខាន់។ ហានិភ័យនេះក៏អាចកើតឡើងពីការប្រើប្រាស់សម្ភារៈដែលមានរក្សាសិទ្ធិដោយអ្នកផ្គត់ផ្គង់ម៉ូដែល។

### យុទ្ធសាស្ត្របង្ការ និងកាត់បន្ថយ

  (តំណយោង:[A06:2021 – Vulnerable and Outdated Components](https://owasp.org/Top10/A06_2021-Vulnerable_and_Outdated_Components/))

៥. ដើម្បីបន្ថយហានិភ័យអាជ្ញាប័ណ្ណ AI បង្កើតបញ្ជីអាជ្ញាប័ណ្ណទាំងអស់ដោយប្រើ BOM និងធ្វើសវនកម្ម software, tools និង datasets ជាប្រចាំ ដើម្បីធានាការអនុលោម និងភាពច្បាស់លាស់តាម BOM។ ប្រើឧបករណ៍គ្រប់គ្រងអាជ្ញាប័ណ្ណស្វ័យប្រវត្តិ សម្រាប់តាមដានពេលវេលាពិត និងបណ្តុះបណ្តាលក្រុមការងារអំពីប្រភេទអាជ្ញាប័ណ្ណ។ រក្សាទុកឯកសារអាជ្ញាប័ណ្ណលម្អិតក្នុង BOM និងប្រើឧបករណ៍ដូចជា [Dyana](https://github.com/dreadnode/dyana) សម្រាប់វិភាគ dynamic software ភាគីទីបី។
៦. ប្រើតែម៉ូដែលពីប្រភពដែលអាចបញ្ជាក់បាន និងប្រើការត្រួតពិនិត្យភាពត្រឹមត្រូវរបស់ម៉ូដែលដោយ signing និង file hash ដើម្បីបន្ថែមភាពជឿជាក់។ ដូចគ្នានេះផងដែរ ប្រើ code signing សម្រាប់កូដដែលបានផ្គត់ផ្គង់ពីក្រៅ។

#### សេណារីយ៉ូ #៣: ការកែលម្អម៉ូដែលពេញនិយម

#### សេណារីយ៉ូ #៤: ម៉ូដែលដែលបានបណ្តុះបណ្តាលជាមុន

#### សេណារីយ៉ូ #៥: អ្នកផ្គត់ផ្គង់ភាគីទីបីដែលត្រូវបានសម្របសម្រួល (Compromised Third-Party Supplier)

អ្នកផ្គត់ផ្គង់ភាគីទីបីដែលត្រូវបានសម្របសម្រួលផ្តល់ LoRA adapter ដែលងាយរងគ្រោះដែលកំពុងត្រូវបានរួមបញ្ចូលទៅ LLM ដោយប្រើ model merge នៅលើ Hugging Face។

#### សេណារីយ៉ូ #៦: ការចូលបំពានអ្នកផ្គត់ផ្គង់

អ្នកវាយប្រហារចូលបំពានទៅកាន់អ្នកផ្គត់ផ្គង់ភាគីទីបី ហើយបំពានដំណើរការផលិត LoRA adapter (Low-Rank Adaptation) ដែលមានបំណងប្រើសម្រាប់បញ្ចូលទៅក្នុង LLM នៅលើឧបករណ៍ ដោយប្រើ frameworks ដូចជា vLLM ឬ OpenLLM។ LoRA adapter ដែលត្រូវបានបំពាននេះ ត្រូវបានកែប្រែបន្តិចបន្តួច ដើម្បីបញ្ចូលភាពងាយរងគ្រោះ និងកូដអាក្រក់។ ពេល adapter នេះត្រូវបានបញ្ចូលទៅក្នុង LLM វានាំឲ្យអ្នកវាយប្រហារមានច្រកសម្ងាត់ចូលទៅប្រព័ន្ធ។ កូដអាក្រក់អាចដំណើរការពេលប្រើម៉ូដែល ហើយអាចធ្វើឲ្យអ្នកវាយប្រហារបំពានលើលទ្ធផលនៃ LLM។

### សេណារីយ៉ូ #៧: ការវាយប្រហារ CloudBorne និង CloudJacking

ការវាយប្រហារទាំងនេះផ្តោតលើហេដ្ឋារចនាសម្ព័ន្ធ cloud ដោយប្រើប្រាស់ធនធានរួម និងភាពងាយរងគ្រោះនៅក្នុងស្រទាប់ virtualization។ CloudBorne គឺជាការប្រើប្រាស់ភាពងាយរងគ្រោះ firmware នៅបរិស្ថាន cloud រួម ដើម្បីបំពានម៉ាស៊ីនបម្រើផ្ទាល់ដែលផ្ទុក virtual instances។ CloudJacking មានន័យថា ការគ្រប់គ្រងឬប្រើប្រាស់ cloud instances ដោយគំនិតអាក្រក់ ដែលអាចនាំឲ្យមានការចូលប្រើដោយគ្មានការអនុញ្ញាតទៅកាន់វេទិកាដាក់ឲ្យប្រើ LLM សំខាន់ៗ។ ការវាយប្រហារទាំងនេះបង្កហានិភ័យធំសម្រាប់ខ្សែសង្វាក់ផ្គត់ផ្គង់ដែលពឹងផ្អែកលើម៉ូដែល ML នៅលើ cloud ព្រោះបរិស្ថានដែលត្រូវបានបំពានអាចបង្ហាញទិន្នន័យសំខាន់ ឬជួយបង្កើតការវាយប្រហារបន្ថែម។

### សេណារីយ៉ូ #៨: LeftOvers (CVE-2023-4969)

ការវាយប្រហារ LeftOvers ប្រើ memory របស់ GPU ដែលលេចធ្លាយ ដើម្បីស្កេនយកទិន្នន័យសំខាន់។ អ្នកវាយប្រហារអាចប្រើវិធីនេះដើម្បីបញ្ចេញទិន្នន័យសំខាន់ពីម៉ាស៊ីនបម្រើផលិតកម្ម និង ការអភិវឌ្ឍន៍​​ workstation ឬ laptop។

### សេណារីយ៉ូ #៩: WizardLM

បន្ទាប់ពី WizardLM ត្រូវបានដកចេញ អ្នកវាយប្រហារប្រើប្រាស់ការចាប់អារម្មណ៍លើម៉ូដែលនេះ ដោយបោះពុម្ពផ្សាយម៉ូដែលក្លែងក្លាយដែលមានឈ្មោះដូចគ្នា ប៉ុន្តែមាន malware និង backdoors។

### សេណារីយ៉ូ #១០: សេវាកម្មរួមបញ្ចូល/បំប្លែងទម្រង់ម៉ូដែល (Model Merge/Format Conversion Service)

អ្នកវាយប្រហាររៀបចំការវាយប្រហារដោយប្រើសេវាកម្ម ការរួមបញ្ចូលម៉ូដែល ឬ ការបម្លែងទ្រង់ទ្រាយ ដើម្បីបំពានម៉ូដែលដែលអាចចូលប្រើសាធារណៈ ដោយបញ្ចូល malware។ នេះជាការវាយប្រហារពិតដែលបានផ្សាយដោយ vendor HiddenLayer។

### សេណារីយ៉ូ #១១: វិស្វកម្មបញ្ច្រាសកម្មវិធីទូរស័ព្ទ (Reverse-Engineer Mobile App)

អ្នកវាយប្រហារធ្វើការវិភាគបញ្ច្រាស (reverse-engineer) កម្មវិធីទូរស័ព្ទ ដើម្បីជំនួសម៉ូដែលដោយម៉ូដែលដែលបានបំពាន ដែលនាំឲ្យអ្នកប្រើទៅកាន់គេហទំព័រសកម្មភាពបោកប្រាស់។ អ្នកប្រើត្រូវបានលើកទឹកចិត្តឲ្យទាញយកកម្មវិធីដោយផ្ទាល់តាមបច្ចេកទេសវិស្វកម្មសង្គម។ នេះជាការវាយប្រហារពិតប្រាកដលើ AI ការទស្សន៍ទាយ ដែលប៉ះពាល់ទៅកម្មវិធី Google Play ចំនួន ១១៦ រួមមានកម្មវិធីសុវត្ថិភាព និងសុវត្ថិភាពសំខាន់ៗសម្រាប់ស្គាល់លុយ, ត្រួតពិនិត្យមាតាបិតា, ស្គាល់មុខ, និងសេវាហិរញ្ញវត្ថុ។
  (តំណយោង: [real attack on predictive AI](https://arxiv.org/abs/2006.08131))

### សេណារីយ៉ូ #១២: ការបំពុលសំណុំទិន្នន័យ

អ្នកវាយប្រហារបំពុលសំណុំទិន្នន័យសាធារណៈ ដើម្បីបង្កើត back door ពេលកែលម្អម៉ូដែល។ back door នេះជួយអោយក្រុមហ៊ុនខ្លះទទួលអត្ថប្រយោជន៍ក្នុងទីផ្សារផ្សេងៗ។

### សេណារីយ៉ូ #១៣: គោលការណ៍ T&Cs និងភាពឯកជន

អ្នកបើកប្រតិបត្តិ LLM ប្រែប្រួលគោលការណ៍ T&Cs និងគោលការណ៍ឯកជនភាព ដោយតម្រូវឲ្យអ្នកប្រើប្រាស់បដិសេធច្បាស់លាស់ពីការប្រើទិន្នន័យកម្មវិធីសម្រាប់បណ្តុះបណ្តាលម៉ូដែល ដែលបណ្តាលឲ្យមានការចងចាំទិន្នន័យសំខាន់។
